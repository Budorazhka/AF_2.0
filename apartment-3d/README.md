# 3D-планировки Aurum Fort

Объёмные реконструкции всех восьми типов квартир, которые есть на сайте. Модели
строятся кодом из размеров поэтажного плана — без внешних библиотек и без интернета.

```
python build.py            # собрать все квартиры
python build.py 66 26-1    # собрать выбранные
node cutaway.test.cjs      # проверить режим «срез стен» и чистоту столешниц
node ../js/residence-media.test.cjs   # проверить привязку к шахматке
```

## Что где лежит

| Файл | Назначение |
| --- | --- |
| `lib.py` | примитивы (`box`, `wall`, `slab`, `band`, `glazing`…), экспорт GLB, сборка вьюера |
| `units/u*.py` | геометрия одной квартиры: контур, стены, проёмы, мебель |
| `build.py` | собирает квартиры, проверяет пересечения, раскладывает файлы |
| `viewer-template.html` | вьюер на чистом WebGL: вращение, вид сверху, срез стен, скрытие мебели и фасада |
| `units-out/<слug>/` | результат сборки: `apartment.glb`, `scene.json`, автономный `index.html` |
| `../assets/residences/<слug>/` | то, что забирает сайт: `model.html` (iframe в шахматке) и `apartment.glb` |

## Как снимались размеры

Источник — `aurum-fort-floor-plans.pdf` (векторный экспорт из ArchiCAD). Масштаб берётся
от несущих колонн: они 40×40 см и в PDF занимают ровно 4,06 пункта, то есть
0,0985 м/пункт. Контуры квартир извлекаются как залитые полигоны — их площади
совпадают с таблицей этажа (70,1 / 51,7 / 38,9 / 35,7 / 26,1 / 21,6 м²), поэтому
границы и осевая сетка заданы точно, а не на глаз. Планировки на сайте
(`assets/img/plans/`) задают расстановку мебели, чертёж — стены и проёмы.

Общее для всех: потолки 2,80 м, двери 2,20 м, внешние стены 20 см, колонны 40×40 см
выступают внутрь помещения на 20 см. Ось Y направлена вверх, единицы — метры,
модели открываются в Blender и Three.js как обычный glTF 2.0.

## Проверки при сборке

`build.py` не выпускает модель, пока мебель пересекает стену или колонну: именно так
в квартире 66 колонна оказалась поверх варочной панели, а холодильник — в углу колонны.
Вторая проверка ловит мебель, уехавшую за пределы квартиры. `cutaway.test.cjs`
дополнительно следит, чтобы в режиме среза стены и высокие шкафы опускались ниже
столешницы, а над проёмами не оставалось перемычек.

## Весь дом для 3D-выбора квартиры (/flats-3d)

```
python building.py                       # здание из того же PDF → assets/data/building-3d.json
python window_views.py путь/к/af.mp4     # виды из окон из промо-ролика → assets/residences/views/
python panorama.py af.mp4 DJI_0975.MP4 DJI_0965.MP4   # 360°-панорамы прогулки → views/pano-2 … pano-7.webp
node ../js/flats-3d/building-data.test.cjs   # все 33 квартиры шахматки есть в 3D, с окнами и моделью
node ../js/flats-3d/sun.test.mjs             # положение солнца и часы солнца в окнах
```

`building.py` разбирает все листы: подвал пропускается, лист 2 — СПА (−1), 3 — лобби (1),
4–9 — этажи II–VII, 10 — крыша. Листы с III по крышу сдвинуты на 9,8 / −5,0 pt, сдвиг
находится по колоннам (на крыше — по шахте лифта). Квартиры — это полупрозрачные «зоны»
ArchiCAD, их узнают по площади (допуск 3,5 %); стены восстанавливаются как промежутки между
зонами на сетке 5 см. Промежуток между квартирой и улицей или террасой становится
остеклением, между террасой и улицей — стеклянным ограждением. Коридоры не зоны: их
замыкают линии стен с чертежа, а на VI–VII этажах коридор берётся с II этажа (ядро
одинаковое). Террасы пентхаусов нарисованы только досками настила, бассейн на крыше — узорной
заливкой, поэтому их проще найти по цвету на отрисованном листе. Подложка этажа
(`assets/residences/plans/floor-N.webp`) — линии того же листа без размеров и текста.

Ориентация не север-вверх: низ листа смотрит на море, то есть на запад (терраса 201,
балконы 204–206), левый край — на Батуми (север). Это `planDownAzimuth` в JSON. Если
заказчик даст точный азимут фасада, правится одно число, солнце и виды пересчитаются.

Вид из окна в прогулке — панорама на основе фото: смоделированный пейзаж в прогулке скрыт, вокруг квартиры
сфера с 360°-панорамой своего этажа (`pano-N.webp`). `panorama.py` берёт сторону моря из облёта
`DJI_0975` (дрон поднимается вдоль дома, кадр на нужной высоте; дом, попавший в кадр слева,
заменяется кадром до него). Вокруг — поворот дрона над крышей из `DJI_0965` (57–102 с, ~200°:
склон, гора с крестом, бухта, Батуми; угол между кадрами меряется фазовой корреляцией и
привязан к кадру с моря по одной башне Батуми), юг — кадр из `af.mp4`. Небо над съёмкой и
земля под ней исходно заполнены градиентом в цветах кадров. `DJI_0972` (земля в лесу вблизи) и `DJI_0952`
(облёт с камерой вниз) для вида из окон не подошли. Это временная замена: настоящая сферическая панорама с дрона
на высоте этажа (режим «Сфера») подставляется один в один в те же файлы.

### Дорисовка панорам

После `panorama.py` выполните `python apartment-3d/pano_fill.py prepare` из корня
репозитория. Скрипт сохраняет исходники как `pano-work/pano-N.raw.webp` (если
копий ещё нет) и готовит перспективные ракурсы в `pano-work/views/` с масками:
белое разрешено редактировать, чёрное — сохранять. Передайте каждый непустой
ракурс с его маской в редактор изображений, попросив продолжить лесистый склон
при том же дневном освещении, без новых крупных объектов, моря, города, людей
и машин. Сохраните квадратные результаты в `pano-work/edits/` с теми же именами
без `.mask`. Затем запустите `python apartment-3d/pano_fill.py compose`.

Генерация выполняется отдельно; сохранённые результаты позволяют повторить
сборку без новых запросов. Общий набор ракурсов этажа 7 используется для всех
этажей только если их маски совпадают; при различиях скрипт остановится.
Пиксели, полностью покрытые съёмкой, сохраняются точно, переходы смешиваются
по маске. Ниже границы съёмки и в её пробелах — сгенерированные фрагменты,
не фотография. Небо выше +20° остаётся исходным, от +5° до +20° переход
к нему плавный. Для точного сохранения
пикселей итог кодируется WebP lossless (quality 80 управляет сжатием).
Если исходные панорамы пересобраны из видео, для новой обработки сначала
вручную замените соответствующие raw-копии и подготовьте новые генерации.

В обзоре дома видны рамы фасада, нижние террасы, лес, дорога, парковка, море и Батуми
(`js/flats-3d/site.js`). В прогулке все этажи остаются на месте. На выбранном этаже
`building.setWalk` вырезает из общей геометрии участок детальной квартиры и её террас.
По выходе восстанавливается исходная геометрия. За зданием видна панорама этажа. Фасадные
рамы строятся по кромкам `facade` из JSON (`js/flats-3d/facade.js`), парковка — по
местам с листа I этажа (`parking`).

Кадры промо-ролика (`af.mp4`) остаются в карточке квартиры как «вид с дрона». Титры
поверх неба и моря заретушированы, кадры с титрами на облаках обрезаны ниже титров.
Сторона «запад» для этажей 2–4 — низкий кадр над кронами, для 5–7 — кадр с крыши дома.

### Контрольные ракурсы прогулки

- [x] Вернуть в вид из окон, с балконов и террас видимые части дома для всех планировок.
  При взгляде вдоль фасада должны читаться соседние секции, при взгляде вниз и вверх —
  перекрытия и балконы на тех этажах, где они есть по плану. Панорама остаётся дальним
  фоном. Проверить со стороны интерьера, что стены и рамы выбранной квартиры не двоятся.
  Контрольные ракурсы — с террасы №401 в сторону окна спальни и вниз вдоль фасада,
  с обычного балкона и с террасы верхнего этажа, где меняется контур здания.
- [x] Проверить все восемь планировок на рябь от наложения поверхностей.
  В прогулке пройти от входа через комнаты к окнам и на балкон или террасу,
  осматривая стыки вблизи и под углом. Сравнить варианты отделки и вид с мебелью
  и без неё, чтобы охватить детали, которые добавляет просмотрщик. Отметить места,
  где узор мерцает или один материал проступает сквозь другой при движении камеры.
  Контрольные места — встроенная техника в №406, №604 и №704, стык паркета и плитки
  у санузла №406, швы шкафов и угол столешницы в №403. Эти примыкания проверяет
  `python apartment-3d/test_walk_surfaces.py`. Геометрию перекрытий дома проверяет
  `node --test js/flats-3d/storey-surfaces.test.mjs`.
- [x] Закрыть просветы под остеклением. В спальне №401 на месте прежней щели
  шириной 5 см нижний профиль соединён с полом порогом на всю глубину проёма.
- [x] Свернуть подсказку об управлении 3D-просмотром в кнопку «?». По умолчанию
  кнопка занимает только своё место. По нажатию рядом открывается текст для
  текущего режима, по повторному нажатию подсказка закрывается. На телефоне
  показывать инструкции для жестов, на компьютере — для мыши и клавиатуры.

## Интерьерные визуализации

Вкладка «Вариант ремонта» в шахматке берёт пять ракурсов из
`assets/residences/<слug>/01-overview.png … 05-bathroom.png`. Сейчас они есть только
у 40,5 («Ар-деко», промпты — в `art-deco-2026/prompts.md`); у остальных типов вкладка
показывает заглушки. Чтобы подключить новый набор: положить пять файлов в папку
квартиры и добавить название стиля в `interior` соответствующей записи
`UNITS` в `js/residence-media.js`.
